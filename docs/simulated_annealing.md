# Simulated Annealing

[編集用テンプレート](../src/lib/search/simulated_annealing.nim)

[N=100の順列を昇順にするサンプル](../src/examples/simulated_annealing/sorting.nim)

1ファイルをコピーして使う焼きなましの枠組み。共通の`header.nim`を先頭でincludeする。
コピー先に合わせてinclude先を直す。coreやコールバック登録の仕組みは持たない。

## 編集箇所

- `State`・`Action`・初期評価値を用意する。
- `propose`で合法な近傍を1つ作る。Stateを変えず、候補がなければfalseを返す。
- `moveForward`で状態と評価値を更新する。
- `moveBackward`で棄却された変更を完全に戻す。

`evaluate`は既定で`state.score`を参照する。`copyState`は値としてのコピー。
変更する領域をref/ptrで共有するStateでは、独立した複製を作るよう書き換える。
初期状態・探索中の状態・保存した最良状態を互いに独立させる。

```nim
let answer = simulatedAnnealing(initial,
    timeLimitSec = 1.9, startTemperature = 10.0, endTemperature = 0.1)
echo answer.score
# answer.stateが最良解。iterationsは候補生成の試行数、acceptedは受理数。
```

既定は最小化・線形冷却。最大化は`minimize = false`。
温度は評価値の差と同じ単位で設定する。温度0では悪化を受理しない。同点は受理する。
評価差はfloatへ変換して比較するため、極端に大きい整数評価値などは差分の計算式を調整する。

終了条件は経過時間だけ。時刻取得・時間制限の確認・温度更新を、既定で256試行ごとにまとめて行う。
時間制限は1回の処理の途中では中断しないため、厳密な締切ではない。
重い近傍では`temperatureUpdateInterval = 1`などへ変更する。

温度は`temperatureUpdateInterval = 256`試行ごとに更新し、間の試行では保持する。
1・2・4・8・…の正の2冪だけ指定でき、それ以外は例外になる。
更新判定は`(iterations and (temperatureUpdateInterval - 1)) == 0`。
`temperatureUpdateInterval = 1`なら毎試行確認・更新する。
候補なしの試行も回数に含む。`timeLimitSec = 0`なら探索せず初期状態を返す。
seedで乱数列は指定できるが、時間制限で試行数が変わるため結果の完全再現は保証しない。

## 差分を先に評価できる場合

AHC073のように変更前の状態から評価差を計算できる問題では、探索ループを直接編集する。
`propose`後に差分評価し、受理された場合だけ変更とキャッシュ更新を行えば、巻き戻しは不要になる。
最良解保存・温度式・乱数生成も問題に合わせて変更する。高速化は同条件で測定してから採用する。

## 順列をソートするサンプル

入力は1..100の順列100個。先頭にNは付けない。出力は探索で得た最良の順列。
標準エラー出力には評価値・試行数・受理数を出す。

各数字について「前の数字が自分より大きい」「自分が次の数字より大きい」を各1点とする。
端では存在する隣だけを見る。したがって評価値は降順の隣接ペア数の2倍で、0なら昇順。
元の位置との距離や、隣接していない数字との大小は評価しない。

近傍はランダムな異なる2点のswapと、1要素のランダムな位置への挿入を半々で選ぶ。
位置の選択に値や評価値を使わない。挿入先は移動後の配列でのインデックスを表す。
仮適用後、悪化する変更も温度に応じて受理する。棄却時はswapなら同じ2点を再交換、
挿入なら逆方向に移動して戻す。評価値は変化する境界だけを差分更新する。
近傍生成・swapはO(1)、挿入は配列をずらすためO(N)。

```sh
nim cpp -d:release -o:build/sorting src/examples/simulated_annealing/sorting.nim
./build/sorting < in.txt
```

固定seed=42、時間制限1秒、温度0.5から0.01の指数冷却。評価値0なら早期終了する。
温度は`startTemperature * exp(ln(endTemperature / startTemperature) * progress)`とする。
開始・終了温度はともに正の値を指定する。
このサンプルも`temperatureUpdateInterval = 256`が既定で、正の2冪で変更できる。
`-d:SortingTimeLimitMs=2000`などで時間制限を変えられる。時間内での整列を保証するものではなく、
未達なら評価値が正の最良順列をそのまま返す。通常のソート処理による補完は行わない。

変更前のswapのみ・固定200万試行・毎試行温度更新での測定では、ランダム順列96件の完全整列は0/96件。
降順になった隣接ペア数は平均49.70から7.58へ減り、終了時は6〜9ペアだった。
逆順は99から6、`2,3,...,100,1`は1から1。整列済み入力は0試行で終了した。
これら4種の固定入力（もう1件は小大交互）を含む計100件の実行時間は平均約0.154秒。
時間はプロセス起動を含むローカル測定値。ランダム入力はPythonのseed=0..95で生成した。
現在のswap・挿入の差分評価と巻き戻しは、10順列×2近傍×全ての異なる2点の198,000通りで、
debug/releaseとも全評価と一致した。
swap・挿入を半々、時間制限1秒、256試行ごとの温度更新でランダム順列20件（入力seed=0..19）を
実行した結果、完全整列は0/20件。降順の隣接ペア数は平均50.5から5.4へ減り、終了時は5〜6ペアだった。
時間制限による探索なので、試行数や結果は実行環境・負荷で変わる。
