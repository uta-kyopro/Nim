# Skip Tour Beam Search

[編集用テンプレート](../src/lib/search/skip_tour_beam.nim) / [探索エンジン](../src/lib/search/skip_tour_beam_core.nim) / [基本例](../src/examples/skip_tour_beam/basic.nim) / [AHC021例](../src/examples/skip_tour_beam/ahc021.nim)

`skipTourBeam`は、世代スキップを扱う独立した差分更新ビームサーチ。
1ターン遷移専用の[tourBeam](tour_beam.md)は変更せず、親・兄弟リンク型の[skipBeam](skip_beam.md)とも独立したコードを持つ。
固定ビーム幅で動作し、時間計測・時間による打ち切り・可変幅は持たない。

## 方式

Stateは1つだけ保持する。木の辺に相当するActionと、その辺を進む・戻るオイラーツアーを連続配列で保持する。
将来世代の選抜器が参照する親は、展開せずに経路だけ残す。現在世代で選ばれた子だけを適用して展開する。

世代を進める際は、現在の候補と将来候補の親を印付けし、ツアーを走査して必要な祖先を求める。
不要な枝を除去して配列を詰め、親番号をまとめて更新する。祖先ごとの参照数更新や親・兄弟リンクの付け替えは行わない。
全経路に共通する先頭は接頭辞の配列へ分離する。Stateは最後に展開した葉の位置に保持し、世代末に根へ戻さない。
保持するActionの連続区間は`supportsCopyMem(Action)`がtrueなら一括コピーし、参照管理が必要な型では通常代入する。

候補は親の配列位置ごとに計数整列する。旧ツアーを逆から読み、前世代の末尾に近い枝から次世代を展開する。
同じ親から追加する子は選抜スロット順。次のツアーもこの巡回順で作るため、世代ごとに巡回方向が反転する。
待機経路の走査ではStateを動かさず、実際に候補を展開する時だけ、前の位置から必要な共通祖先へ戻って差分を適用する。
現在地のAction列と、親番号変換表で更新する経路位置を保持するので、現在地の枝が配列から消えても巻き戻しに必要な情報は残る。
候補がない空の世代では、適用も巻き戻しも行わない。
現在世代の候補を取り出したあと、未来の選抜器に候補が残っていない層では専用経路を使う。
親の印付け・祖先への伝播・ツアーのフィルタ処理を省き、旧ツアーを1回巡回して採用枝だけを残す。
全候補が`step=1`なら継続してこの経路を使える。未来候補が残る層では従来の保持処理を使う。
専用経路の展開中に`step>1`が登録されても、その親を残して次世代へ引き継ぐ。
skipBeamやtourBeamと同点処理・展開順は一致せず、得点や選抜件数が変わる場合がある。

## 編集箇所とAPI

`State`（`isFinished: bool`を含む）、`Action`、`evaluate`、`getHash`、`moveForward`、`moveBackward`、`expand`を定義する。
編集用テンプレートの評価値とHashは既定で`state.score`と`state.hash`を参照する。
Actionには適用と巻き戻しに必要な情報を持たせる。複数世代の操作を1つのActionにまとめてよい。

```nim
proc expand(s: var State, f: var SkipTourBeamFrontier[Action, int, uint64]) =
    # TODO: 合法なActionと、その操作が消費する世代数を列挙する。
    for action in legalActions(s):
        s.pushCandidate(f, action, step = action.consumedTurns)

defineSkipTourBeam(search, State, Action, int, uint64)
let answer = search(initial, beamWidth = 1000, maxTurns = 2000)
for action in answer.actions:
    state.moveForward(action)
```

- `pushCandidate(state, frontier, action, step = 1, group = -1)`：仮適用して評価・必要時のHash取得・巻き戻しを行い登録する。
- `frontier.push(action, score, key, finished = false, step = 1, group = -1)`：遷移後の評価値・Hashで直接登録する。
- `frontier.canImprove(score, step = 1, finished = false, group = -1)`：Hash計算前に足切りする。
- `frontier.remainingTurns()`：展開中の状態から世代上限までの残りを返す。
- `search(initial, beamWidth, maxTurns = 2000, minimize = true, groupLimit = 0, groupCount = 0)`：探索を行う。

`step`は正の消費世代数。上限を超える候補は登録しない。世代ごとの選抜器で独立にHash重複を除き、同じHashなら良い評価の候補へ置き換えられる。
親は展開中の位置から自動設定する。Hashには将来の遷移に影響する情報を反映する。整数Hashは再ハッシュせず使用するため、差分ZobristHashを推奨する。

`groupLimit > 0`では`beamWidth`による全体上限の代わりに、各グループ最大`groupLimit`件を選ぶ。
`groupCount`はグループ数。ID順に安定ソート・Hash重複除去を行い、先のグループを優先する。

## 戻り値と注意点

`SkipTourBeamResult[Action, Score]`は`score`、`actions`、`turns`、`status`、`selectedCandidates`を返す。
`turns`は消費世代数の合計で、`actions.len`とは異なる。Action列の復元はライブラリが行う。
空の世代でも将来候補があれば継続する。完了候補は到達世代まで待機し、その世代で最初の完了候補を返す。
`beamMaxTurns`、`beamFinished`、`beamExhausted`で終了理由を区別する。
候補が尽きた場合は、最後に候補が存在した世代の最良Action列を返す。
`selectedCandidates`は各到達世代の選抜件数と完了候補数（最大1）の累計。

初期Stateは値として受け取る。State内部のref/ptr共有領域は必要に応じて独立させる。
`expand`はStateを元に戻して終了する。Action内の参照先を探索中に変更しない。

祖先を含む保持辺数をE、待機中の全候補数をP、現在世代の選抜件数をWとすると、
世代更新の管理処理はO(E + P + W + D)。Dは現在地や接頭辞のAction数で、世代の最初の移動時に共通祖先を調べる。
これに実際のAction適用・巻き戻し・候補生成・選抜が加わる。
保持辺ごとのID列は追加せず、既存の親番号変換表を再利用する。現在地のAction列・位置列と接頭辞にO(D)の領域を使う。
待機経路が多い場合は配列の走査・コピー量が増えるため、常にskipBeamより高速とは限らない。

## 検証

独立したStateコピー・線形選抜の参照実装と、ランダムDAG 200個×評価方向2通り×幅5通り×グループ上限3通りの6,000条件を比較する。
評価・正確なAction列・到達世代・終了理由・選抜件数を照合し、復元したAction列も再生する。
空の世代、stepによる上限超過、将来世代の完了、候補枯渇、初期完了、500世代のref型Actionも確認する。
根から60世代先への待機候補を残すテストでは、2世代ずつ進む候補を選び、展開間の巻き戻し0回を確認する。
2本の枝を維持するテストでは、各世代の展開順が1→2、2→1と反転することを確認する。
テスト・測定スクリプト・生データはローカル専用。

## Stateの完了フラグ

編集用テンプレートは`State.isFinished: bool`を持つ。完了判定用の関数は不要。
初期Stateにも正しい値を設定し、固定ターン探索ならfalseのままにする。
通常beamは`expand`で遷移先の`next.isFinished`を設定してから登録する。
差分更新型の`pushCandidate`は仮適用後の値を読むため、`moveForward`で更新し、
`moveBackward`で以前の値を復元する。展開前のStateのフラグを使い回さない。

```nim
# moveForward内：遷移先の完了状態を保持する
self.isFinished = goalCondition
# moveBackward内では、変更前のisFinishedも復元する
```

`expand`内で評価値・キー・完了判定をまとめて計算する場合は、既存の`push`へ
`finished = goalCondition`を直接渡してもよい（通常beamでは遷移後Stateも渡す）。
初期状態の完了判定にはState側のフラグが必要。
`State`には実在する`isFinished: bool`フィールドが必須。
旧`proc/template isFinished(state): bool`形式は受け付けない。
フラグが将来の動作を区別する情報なら、同一キーで異なる状態を混ぜないようにする。

## 葉の評価値・Hash

採用候補の生値を保持し、`expand`直前に`frontier.currentScore`・
`frontier.currentHash`へ渡す。初期値は`evaluate(initial)`・`getHash(initial)`。
`getHash`は直接`push`する実装でも必要となる。

巡回だけを軽くする場合は`moveBoardForward`・`moveBoardBackward`で盤面・
巻き戻し履歴・`isFinished`だけを更新し、`loadLeaf(state, leafScore, leafKey)`で
評価値・Hashを復元する。この3つはセットで実装する。
盤面フックを省略した場合は従来の`moveForward`・`moveBackward`を使う。
`pushCandidate`の一時評価と最終Action列の再生には通常の遷移を使う。
評価値がStateの保持値と異なる場合は`loadLeaf`で逆変換する。
生値だけから復元できない成分は盤面フックでも更新する。

巡回中の評価用フィールドは古い値なので、盤面フックから参照しない。
`expand`は候補を作るたびに盤面・評価値・Hashを元へ戻す。
