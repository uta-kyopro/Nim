# C++バックエンドの128bit整数

`src/lib/math/int128.nim`は、符号付き`Int128`と符号なし`UInt128`を提供する。GCC/Clangの`__int128`を使うため、**`nim cpp`と128bit整数をサポートする対象環境**が必要。GMPなどの外部ライブラリには依存しない。

| 型 | 範囲 |
|---|---|
| `Int128` | -2^127 .. 2^127-1 |
| `UInt128` | 0 .. 2^128-1 |

Nim 2.2.4 / Windows amd64 / MinGW GCC 11.1.0でdebug・releaseを検証した。他のコンパイラ・対象環境は未検証。

## 初期化と演算

```nim
import ../src/lib/math/int128

let a = initInt128(123)
let b = parseInt128("123456789012345678901234567890")
echo a + b
echo b div a
echo b mod a
echo initInt128(1) shl 100
echo low(Int128), " .. ", high(Int128)

var u = initUInt128(7)
u *= initUInt128(6)
echo u
```

`initInt128`・`initUInt128`には通常整数、128bit整数、十進文字列を渡せる。型間の自動変換は行わない。`Int128 + int`や`Int128 + UInt128`は、呼び出し側で型を揃えてから計算する。

`+`・`-`・`*`・`div`・`mod`、単項`-`、比較、`cmp`、`and`・`or`・`xor`・`not`、`shl`・`shr`、`+=`・`-=`・`*=`、`inc`・`dec`、符号付き`abs`に対応する。`hash`も提供するため、`Table`・`HashSet`のキーにできる。

除算はC++と同じゼロ方向の丸め。`-7 div 3 == -2`、`-7 mod 3 == -1`。符号付き右シフトはGCC/Clangの算術右シフト。`UInt128`の加減乗算とビット演算はmod 2^128であり、debugでも桁あふれをエラーにはしない。

## 型変換

```nim
let signed = toInt128(123'u64)
let unsigned = toUInt128(signed)
let normal = toInt[int64](signed)
let byteValue = toInt[uint8](initUInt128(255))
```

`toInt[T]`は`SomeInteger`の型に変換する。`Option`ではなく指定した整数型を返す。debug時は変換先の範囲を検査する。浮動小数点との変換は提供しない。

128bit整数はNim側では外部型なので`SomeInteger`には含まれない。Nimの`const`・`static`内での計算や、`SomeInteger`に制約された既存APIには直接使えない。`high(Int128)`などの値も実行時の`let`で保持する。

## bitの個数・位置・列挙

```nim
let bits = (initUInt128(1) shl 3) or (initUInt128(1) shl 100)
echo bits.popCount()     # 2
echo bits.firstSetBit()  # 4（1始まり）
echo bits.countTrailingZeroBits() # 3（0始まり）
for index in bits.getSetBits():
    echo index          # 3, 100（昇順）
```

| API | 戻り値・動作 | 計算量 |
|---|---|---|
| `popCount(x)` | 立っているbitの数、0..128 | O(1) |
| `countSetBits(x)` | `popCount(x)`と同じ（bitopsの別名にも対応） | O(1) |
| `firstSetBit(x)` | 最下位の立っているbit位置、1..128。ゼロなら0 | O(1) |
| `countTrailingZeroBits(x)` | 非ゼロ入力の下位ゼロ数、0..127 | O(1) |
| `getSetBits(x)` | 立っているbit位置を昇順に列挙。ゼロなら何も返さない | O(popCount(x)) |

`std/bitops`をimport・再exportし、64bit部分の処理にもそのAPIを使用する。各関数と`getSetBits`は`UInt128`・`Int128`に対応し、引数を変更しない。符号付きは128bitの2の補数表現として扱うため、`popCount(initInt128(-1)) == 128`、符号付き最小値は`firstSetBit == 128`、`countTrailingZeroBits == 127`。

`firstSetBit(0)`は両ビルドで0。`countTrailingZeroBits(0)`はbitopsと同じく`-d:noUndefinedBitOpts`指定時のみ0を保証する。それ以外では非ゼロが前提で、debug時はゼロを検査する。`getSetBits(0)`は空の列挙で、返す位置は引き続き0始まり。

## ビット盤面のBFS

最大64セルなら、Cバックエンドでも使える[uint64版](bitboard_bfs.md)も用意している。

[盤面BFSの使用例](../src/examples/int128/bitboard_bfs.nim)は、`row * width + col`をbit位置として、最大128セルの長方形盤面を1つの`UInt128`に保持する。

`bitboardBfs(height, width, walkable, starts)`に通行可能セルと始点のbit集合を渡すと、到達可能セルのbit集合`reachable`と各セルの最短距離`distances`を返す。壁・到達不能セルの距離は-1。始点が空なら全セルが-1で、複数始点の場合は最も近い始点からの距離になる。

各反復でfrontierを上下左右へシフトし、未訪問の通行可能セルだけを次のfrontierにする。左右端のマスクで行の回り込みを防ぎ、有効盤面マスクで128セル未満の盤面外bitを除外する。128bit全体のマスクや1×128盤面は、128bitを128だけシフトしないよう別扱いする。

`frontier.getSetBits()`でその距離のセルを列挙し、`reachable.popCount()`で到達セル数を得る。盤面サイズ、盤面外の通行可能bit、壁上の始点の検査はdebug時のみ。開始点はすべて通行可能セルであることが前提。

```sh
nim cpp -r -d:release --outdir:build/examples src/examples/int128/bitboard_bfs.nim
nim cpp -r -d:debug --outdir:build/tests tests/test_int128_bfs.nim
nim cpp -r -d:release --outdir:build/tests tests/test_int128_bfs.nim
```

1×128・128×1・8×16・盤面の左右端・空のfrontier・到達不能領域、および固定seedのランダム300盤面について、全セルの距離を独立した座標・キューBFSと比較する。速度の優位性は測定していない。

## 入出力

```nim
import ../src/lib/math/int128

let a = input(Int128)
let b = input(UInt128)
echo a
echo b
```

単独でimportした場合、`input`は標準入力から空白区切りのトークンを読む。ファイルからは`readInt128(file)`・`readUInt128(file)`を使用する。`$`・`echo`で十進表記を出力でき、符号付き最小値も扱える。

共通headerを先にincludeしてからimportすると、`input(Int128)`・`input(UInt128)`はheaderの`nxtStr`を利用する。`input(Int128, UInt128)`や`print`も使える。[header併用例](../src/examples/int128/header_input.nim)

十進文字列は任意の桁数の先頭ゼロと任意の`+`符号に対応する。`Int128`では`-`も許可する。文字列内の空白・区切り文字・基数接頭辞は受け付けない。

## debug時の検査

以下の検査はすべて`when defined(debug)`内にあり、違反時は`AssertionDefect`になる。

- 十進文字列の形式と表現範囲。
- 負数からunsignedへの変換、unsignedからsignedへの変換、通常整数への変換範囲。
- signedの加減乗算、単項マイナス、`abs`、左シフトの桁あふれ。
- ゼロ除算、およびsigned最小値を-1で除算・剰余計算する操作。
- シフト数が0..127に含まれること。

通常ビルドでは前提を満たす引数・演算結果を渡す。signedの範囲外演算、ゼロ除算、範囲外シフトは結果を保証しない。signedをunsignedへビット単位で変換したい場合も、負数の通常変換ではなく用途に合う明示的な処理が必要。ストリームのEOFや読み込み失敗はI/Oの例外として通常ビルドでも通知される。
